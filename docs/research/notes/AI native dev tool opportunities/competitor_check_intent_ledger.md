# Competitor Check: "Intent Ledger" (distilled, code-anchored, drift-checked decision records for agent-written code), as of October 31, 2026

Scope reminder. The idea has 5 parts: (1) DISTILL structured decision records (decision, constraints, rejected alternatives and why, assumptions, approver) from agent sessions + PRs/issues/chats; (2) ANCHOR them semantically to code regions so they survive refactor/rename/rebase/squash; (3) QUERY ("why is this like this?", "was X tried?") with agents required to consult it (e.g., MCP); (4) INTENT-DRIFT DETECTION before merge, including reintroduction of a rejected alternative; (5) portable, git-native, open, vendor-neutral format.

Method note: adversarial search (aimed at proving the idea is NOT new). About 40 searches and fetches across vendor docs, GitHub READMEs, PyPI, HN showcase mirrors, arXiv, and trade press. Several GitHub pages returned 404 or 403 at fetch time (cursor/agent-trace repo, GrayCodeAI/across, mcpservers.org Nauro page). Those are noted where relevant.

## Q1. What do the named incumbents and adjacent tools do today? Do they distill decisions and rejected alternatives, anchor semantically, and detect intent drift?

### Takeaway
Every one of the five parts has already been shipped by someone, usually in more than one place. No product found combines all five. The two closest are **Entire** (well funded; captures sessions from 8 agents; Brain memory of "why a decision was made, what was tried before"; MCP; line-level `why`/`blame`; no drift detection) and **Decispher** (proprietary SaaS; multi-source extraction from Slack/GitHub/Jira plus agent-session hooks; MCP; claims PR-blocking on contradiction, though its open-source Decision Guardian part matches on paths and regex, not meaning). Neither uses semantic anchoring, and neither treats "rejected alternatives" as a first-class field that gets checked at merge time.

### Cited Findings

**Entire (Thomas Dohmke). Checkpoints, Brain, why/blame, review, MCP: about 55–60% of the idea; the strongest well-funded threat**
- Launched Feb 10, 2026 with a $60M seed. Checkpoints is an open-source CLI that links agent sessions to Git commits: "transcript, prompts, files touched, token usage, tool calls" are stored in Git and shown in a UI — [Entire news](https://entire.io/news/former-github-ceo-thomas-dohmke-raises-60-million-seed-round); [The New Stack](https://thenewstack.io/thomas-dohmke-interview-entire/); [Dohmke on X](https://x.com/ashtom/status/2021255786966708280)
- Mechanism: agent hooks collect prompts, transcript, tool activity, changed files, and tokens. A Git hook adds an `Entire-Checkpoint` trailer, and metadata lives on an `entire/checkpoints/v1` branch. The capture docs describe storing RAW context; they do not describe distilled decisions or rejected alternatives — [Entire docs: capture checkpoints](https://docs.entire.com/guides/checkpoints/capture-checkpoints.md); [36kr](https://eu.36kr.com/en/p/3678623948366473)
- Current docs index (Oct 2026) shows a much broader product: `why` ("explains the commit, checkpoint, prompt, and session behind a file or line"), `blame` (line history with checkpoint context), `recap`, `review` (multi-agent code review), `investigate`, `search` (checkpoints, commits, sessions, code), `mcp` (Entire as an MCP server), entire-graph (code index), **Brain** ("shared memory, past decisions, lessons learned"). Supported agents: Antigravity, Claude Code, Codex, Copilot CLI, Cursor, Factory, OpenCode, Pi, plus an open Agent Integration Protocol. No page in the index covers drift — [Entire docs llms.txt](https://docs.entire.com/llms.txt)
- `entire why FILE[:LINE]`: jumps "from a file or specific line to the commit, checkpoint, prompt, and session behind it". There is no symbol-level lookup, and the docs don't say how it handles refactors, renames, or squashes — [Entire docs: why](https://docs.entire.com/cli-reference/why.md)
- **Entire Brain**: a "memory layer for your Git repository" that combines sessions, checkpoints, project memories, docs (including PDF/Word/Excel/PPT under `docs/`), Git history, and entire-graph code context. It captures "why a decision was made, what was tried before, and what your team learned". Setup can extract memories from past sessions using a coding agent. MCP tools: `brain_remember`, `brain_recall`, `brain_brief`, `brain_query`, `brain_status`. Agent instructions are written to `.entire/agent-guide.md` and AGENTS.md/CLAUDE.md, with a "strict" option that makes tool use mandatory. The docs describe no contradiction detection and no blocking mechanism — [Entire docs: Brain overview](https://docs.entire.com/guides/brain/overview.md)
- Brain repo (MIT, about 86 stars, 2,730 commits): facts are organized by taxonomy paths `category.subcategory.type` with categories "architecture, constraints, preferences, project, workflow". Rejected or tried alternatives are NOT a distinct type ("revisit past attempts and their outcomes" goes through sessions and history). Facts live in `facts/<branch>/facts.ndjson`. Retrieval is BM25 lexical (embedding retrieval was removed). Facts carry "source anchors", and `entire brain verify` "checks source references, not whether a conclusion is correct". Entire Graph `inspect impact --symbol` links symbols to checkpoints and sessions. No PR-check integration, but webhooks can notify CI — [GitHub entireio/entire-brain](https://github.com/entireio/entire-brain)
- `entire review` inputs: branch, base ref, profile task text, one-off prompt, and a judge agent. The docs do NOT say it consults Brain, past decisions, or rejected approaches — [Entire docs: review](https://docs.entire.com/cli-reference/review.md)

**Decispher (Context Engine + Memory + Worker; open-source Decision Guardian): about 65–70% of the functionality, but proprietary and not git-native**
- Ingests Slack, GitHub, GitLab, and Jira ("Decisions are extracted from the Slack messages, pull request descriptions and Jira comments your team already writes"). Setup installs hooks for Claude Code, Cursor, Codex, and Grok Build, and sessions are recorded per branch — [decispher.com](https://decispher.com/)
- Seven unit types: decision, convention, constraint, rationale, ownership, history, plan. "History" records failed attempts. There is no named "rejected alternatives" field; examples show "X over Y". Tracks supersessions and conflicts. Cross-source agreement raises confidence — [decispher.com](https://decispher.com/); [dev.to, Ali Abbas, "How Decispher preserves your team's context"](https://dev.to/ali_abbas_d8086e0f96d8173/how-decispher-preserves-your-teams-context-ej5)
- Code linkage is "pointers to files". It never clones the repo, except in a Worker sandbox — [decispher.com](https://decispher.com/)
- Query: 25 MCP tools. It also auto-generates CLAUDE.md, AGENTS.md, .cursorrules, and 6 other instruction files that stay in sync. The author reports about 35–65% fewer tokens (vendor claim) — [decispher.com](https://decispher.com/); [dev.to](https://dev.to/ali_abbas_d8086e0f96d8173/how-decispher-preserves-your-teams-context-ej5)
- Drift: the site claims "Decision Guardian ... blocks a pull request contradicting a decision on record" and that it tracks whether decisions are still current — [decispher.com](https://decispher.com/)
- But the open-source **Decision Guardian** (MIT, about 71 stars, 92 commits) works from HAND-WRITTEN Markdown (`.decispher/decisions.md`) mapped by globs, regex, content match, JSON path, and line ranges. No LLM or semantic contradiction check is mentioned. It surfaces context on a PR and can fail the check on critical matches (`fail_on_critical: true`). Native PR comments work on GitHub Actions only — [GitHub DecispherHQ/decision-guardian](https://github.com/DecispherHQ/decision-guardian); Show HN Feb 2026 and v1.2.0 in Mar 2026 — [HN showcase 46993402](https://hnshowcase.com/post/46993402/decision-guardian-enforce-adrs-on-prs); [HN showcase 47392464](https://hnshowcase.com/post/47392464/decision-guardian-v1-2-0-enforce-architectural-decisions-at-)
- Business: credit-based pricing (50 free credits; from $9 per 100 credits). Product Hunt launch about 2 months before the search date. Founders are not named on the site — [decispher.com](https://decispher.com/); [Product Hunt](https://www.producthunt.com/products/decispher/makers)

**Cursor Agent Trace (open spec): attribution only, no "why"**
- A draft, vendor-neutral JSON "trace record" spec tying code ranges to the model and conversation that produced them. v0.1.0 RFC, Jan 2026, CC BY 4.0. Storage-agnostic (files, git notes, DBs). Contributor types: human/AI/mixed/unknown. Works with Git, Mercurial, and Jujutsu. Early support from Cline, OpenCode, and Git AI. The RFC leaves open how to handle merges, rebases, and large agent-driven changes — [cursor/agent-trace README](https://github.com/cursor/agent-trace/blob/main/README.md); [Thoughtworks Radar](https://www.thoughtworks.com/en-us/radar/platforms/agent-trace); [AI Engineer Guide](https://aiengineerguide.com/til/agent-trace-spec-by-cursor/)
- A GitHub issue proposes building on OpenTelemetry primitives. Adoption not confirmed — [agent-trace issue #6](https://github.com/cursor/agent-trace/issues/6)

**Git AI: line-level AI attribution that survives rebase and squash, no rationale**

Docs: "Rebase correctly merges attribution" and squash "correctly merges attribution". Caveat: web-UI squash and rebase don't update Authorship Logs. Sources conflict on whether prompts are shown per line — [usegitai.com: Git AI 1.0](https://usegitai.com/blog/introducing-git-ai); [usegitai.com: track AI code](https://usegitai.com/track-ai-code)

**Semantica (semanticash/cli): attribution and lineage**
- MIT CLI, about 5 stars. Per-file and per-line AI attribution (commit trailer e.g. "42% claude_code (18/43 lines)"). `explain` gives session context plus optional LLM "playbook" summaries. No decision extraction, drift detection, or MCP. Local SQLite (`lineage.db`); "never writes to Git history" — [GitHub semanticash/cli](https://github.com/semanticash/cli)

**GrayCode**: "GrayCode Trace" not found. GrayCodeAI/Across is described as a "Git-native engineering context, provenance, checkpoint, and continuity system" (search snippet only; the repo returned 404 at fetch) — [search snippet: GitHub GrayCodeAI/across](https://github.com/GrayCodeAI/across)

**SpecStory: raw history, not distilled records**
- Saves agent sessions as Markdown in `.specstory/history/*.md`. The docs suggest committing them "to preserve design intent". An agent-skills plugin summarizes and organizes sessions. Marketing copy says it captures "decisions, debates, and intent", but no structured decision schema or anchoring was found — [SpecStory docs](https://docs.specstory.com/integrations/terminal-coding-agents); [SpecStory newsletter](https://newsletter.specstory.com/p/specstory-in-the-wild-from-ai-session); [skills.sh specstory-session-summary](https://www.skills.sh/specstoryai/agent-skills/specstory-session-summary)

**GitHub Copilot Memory: the incumbent's take on anchoring, deliberately short-lived**
- Repository memories are stored "with citations" to specific code locations. Agents verify the citations in real time against the current branch before use and store corrected memories when code contradicts them. Seeded false memories were "self-healed". Memories auto-delete after 28 days unless re-validated. Repo-scoped. Public preview Jan 2026 in Copilot CLI, the coding agent, and code review — [GitHub blog, Jan 2026](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/); [GitHub docs: Copilot memory](https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/agents/copilot-memory)

**GitHub agentic workflows (gh-aw) "design-decision-gate": PR-time ADR conformance from GitHub itself**
- An agentic GitHub Actions workflow. If a PR lacks an ADR, "AI has analyzed the PR diff and generated a draft ADR" (committed to `docs/adr/NNNN-title.md`). Once an ADR is linked, it "verif[ies] the implementation matches the decision" and lists divergences. Its comments say "This PR cannot merge until an ADR is linked". Triggered by an `implementation` label or more than 100 new lines of core logic. A formatting PR was merged May 21, 2026 — [github/gh-aw PR #33836](https://github.com/github/gh-aw/pull/33836/files)

**Unblocked: "decision-grade context" in review, proprietary**
- Code Review launched Feb 4, 2026. It pulls from Slack, Linear/Jira, docs, and previous PRs to surface "historical, architectural, and social" context on PRs. It has an MCP server and PR summaries. Pricing: $19 per dev per month for review, $29 for platform. No structured decision ledger, code anchoring, or open format found — [Unblocked pricing](https://getunblocked.com/pricing/); [Unblocked blog: context engine for agents](https://getunblocked.com/blog/unblocked-context-engine-for-agents/index.md); [Product Hunt](https://www.producthunt.com/products/unblocked/launches/unblocked-code-review)

- Tessl repositioned toward "Skills on Tessl: the package manager for agent skills"; spec-as-source is still beta — [codemyspec Tessl review](https://codemyspec.com/blog/tessl-review); [Tessl blog](https://tessl.io/blog/my-coding-agent-needed-a-package-manager-for-its-own-brain-and-i-gave-it-one-using-a-skills-registry)

### Inferences
- Coverage matrix of the five parts (best-in-class example for each):
  - (1) Distill: Decispher (multi-source, SaaS), Entire Brain (sessions + docs + git), agent-decisions (Claude Code only), gh-aw (drafts ADR from diff).
  - (2) Anchor: Copilot Memory (citations validated by an agent), Entire Brain (source anchors plus `verify`; graph links symbols to checkpoints), Git AI (attribution survives rebase/squash). **None does semantic, refactor-proof anchoring OF DECISION RECORDS.**
  - (3) Query plus mandatory consult: Entire Brain MCP with "strict" mode, Decispher MCP (25 tools), Nauro `check_decision`, agent-decisions PostToolUse injection.
  - (4) Drift: Decispher (claimed PR blocking; OSS part is path/regex), gh-aw design-decision-gate (LLM conformance to a LINKED ADR), Adrift (see Q2).
  - (5) Open/git-native/vendor-neutral: Lore protocol, CommitLore, agent-decisions, Nauro, Entire Brain (MIT, but tied into Entire platform/graph), Agent Trace (attribution only).
- Entire is the most dangerous competitor. It already has the raw-session capture across 8 agents, a Brain that extracts "why/what was tried" memories, MCP with a mandatory-use mode, line-level `why`, a review command, and CI webhooks. Wiring Brain into `entire review` gives "intent drift detection", which looks like an incremental step for them (inference, not announced).
- Copilot Memory's design (validate citations at use time, expire in 28 days) is the opposite philosophy to a durable ledger. GitHub could still add durable "decision memories" (inference).

## Q2. Small startups, Show HN launches, GitHub repos, and arXiv papers (2024–2026)

### Takeaway
The open-source long tail is crowded and converging fast. At least one repo (agent-decisions) implements DISTILL + ANCHOR + inject-on-touch + git-native for Claude Code, and explicitly lists drift detection as not yet built. Another (Adrift) implements PR-time "design-intent regression" review. Several git-native decision stores (CommitLore, Nauro, lema-mcp, the Lore protocol paper) cover rejected alternatives. Academia has named the problem ("intent debt", "Decision Shadow", "agentic drift"). No dedicated YC company was found.

### Cited Findings
- **agent-decisions (m-zagorski)**: "Decision records your coding agent actually reads. Captured from Claude Code sessions, anchored to code, injected when the agent touches it." Drafts are captured at session end or pre-compaction (sessions without edits are skipped). Records are Markdown + YAML (`id`, `status`, `anchors`, `supersedes`) with body sections Decision / Why / Rejected alternatives, plus `reviewed_by` and `reviewed_at` on approval. Statuses: draft, needs-reason, active, superseded. A PostToolUse hook injects up to 5 decisions per file. Stored in `.context/decisions/`. MIT. Stated limits: "Status: v0, experimental"; "Anchors are paths, so renaming or deleting a file silently disconnects its decisions"; "there is no drift check on code changes yet." 0 stars, 3 commits — [GitHub m-zagorski/agent-decisions](https://github.com/m-zagorski/agent-decisions)
- **Adrift (`adrift-pr`)**: "Open-source PR reviewer that detects design-intent regressions", meaning PRs "that quietly reverse a decision the team already made". It grades diffs against ADRs and PR descriptions (the PR title and description are injected as the author's stated intent). Conservative by default. Learns via `/adrift accept|override <why>|dismiss|flag`. Store in actions/cache, branch-scoped. Positioned as complementary to CodeRabbit — [PyPI adrift-pr](https://pypi.org/project/adrift-pr/)
- **CommitLore**: "git-native decision memory" for Claude Code, Codex, and Cursor. Records stored as git trailers + refs/notes; separates active/superseded/expired; MCP; MIT; TypeScript; about 17 stars — [mcpservers.org commitlore](https://mcpservers.org/servers/monglong0214/commitlore); [Enterprise DNA directory](https://enterprisedna.co/directories/mcp/monglong0214-commitlore)
- **Nauro**: "records the project decisions you approve, including their reasons and rejected alternatives". `nauro adopt` proposes a record for human review. `check-decision` "retrieves prior reasoning; it does not run an agent or change decisions" (advisory). Keyword retrieval with optional embeddings. Plain Markdown. Apache-2.0. 11 stars. No code anchoring or CI mentioned — [GitHub Nauro-AI/nauro](https://github.com/Nauro-AI/nauro)
- **lema-mcp**: a local MCP that checks "whether a direction was already rejected" against recorded RFC/KEP deliberation and returns a typed `ruled_out` verdict with the recorded reason (aggregator page only) — [pkgstats lema-mcp](https://www.pkgstats.com/pkg:lema-mcp)
- **mcp-server-decisions**: an MCP server to record problem, chosen solution, rejected alternatives, and to track whether predictions held — [Glama](https://glama.ai/mcp/servers/Roberton003/mcp-server-decisions)
- **GhostTrace (Show HN)**: logs "Phantom Branches", actions an agent considered and rejected along with the reasoning. It covers runtime behavior, not repo history — [HN 47057488](https://news.ycombinator.com/item?id=47057488)
- **Lore (hsusul/lore)**: a local archive of Claude Code and Codex sessions with an MCP (`search_sessions`, `read_session`). Checks whether agent-written content reached a commit via git object ids ("survives rebases and squashes"). Does NOT extract decisions or detect contradictions. Apache-2.0, 134 stars — [GitHub hsusul/lore](https://github.com/hsusul/lore)
- Enterprise DNA (Aug 17, 2026): "Five different teams, working on nothing to do with each other, all built the same tool and gave it the same name" (Lore: git history as decision memory for coding agents) — [Enterprise DNA AI Pulse](https://enterprisedna.co/resources/ai-pulse/ai-pulse-2026-08-17-five-unrelated-teams-independently-name-their-agent-memory-t)
- Intent-drift prototypes: intent-drift-skill (compares original goal against current plan and changes), IntentDiff (Azure AI Foundry; agent actions checked against a contract), driftguard (flags stale CLAUDE.md/AGENTS.md statements after code changes) — [GitHub shauryagangrade/intent-drift-skill](https://github.com/shauryagangrade/intent-drift-skill); [GitHub MariaJi/intentdiff](https://github.com/MariaJi/intentdiff); [GitHub prateekg7/driftguard](https://github.com/prateekg7/driftguard)
- Practitioner pattern: 141 ADRs plus a rule file to stop Claude Code re-arguing settled choices — [daily.dev](https://daily.dev/posts/ai-coding-agent-context-how-to-document-project-decisions-9jfmtzmeo); an ADRs-as-agent-memory post — [Andrew Connell](https://www.andrewconnell.com/articles/architecture-decision-records-ai-agents/); a BrainGrid blog arguing that recording only the winning option is the most common failure — [BrainGrid](https://www.braingrid.ai/blog/architecture-decision-records-for-ai-coding-agents)
- **arXiv 2603.22106 (Storey)**: "From Technical Debt to Cognitive and Intent Debt". The triple-debt model: technical debt (code), cognitive debt (people), intent debt ("a lack of externalized goals, constraints, and rationale that both humans and AI systems need"). It argues GenAI may reduce technical debt while accelerating cognitive and intent debt. Submitted Mar 23, 2026; also in ACM Queue — [arXiv 2603.22106](https://arxiv.org/abs/2603.22106); [Tech Lead Journal #264](https://techleadjournal.dev/episodes/264/)
- **arXiv 2603.15566 (Stetsenko, Mar 16, 2026)**: "Lore: Repurposing Git Commit Messages as a Structured Knowledge Protocol for AI Coding Agents". Names the "Decision Shadow". Git trailers carry "constraints, rejected alternatives, agent directives, and verification metadata", queryable via a CLI — [arXiv 2603.15566](https://arxiv.org/abs/2603.15566)
- **arXiv 2607.29516**: "From Code Review to Code Critique: Intent, Drift, and Spotlight for AI-Generated Diffs at Scale". Treats "agentic drift" as the gap between developer intent and what the agent produced; intent prediction is a prerequisite for drift detection; 118-sample benchmark (abstract-level only) — [arXiv 2607.29516](https://arxiv.org/html/2607.29516v1)
- Other arXiv: "Reasoning Provenance for Autonomous AI Agents" (2603.21692) — [arXiv](https://arxiv.org/pdf/2603.21692). "Engineering Reliable Coding Agents" (2608.13867) notes that a label like "selected tool A" omits "alternatives, constraints, and evidence" — [arXiv](https://arxiv.org/pdf/2608.13867). TraceCoder (2607.26307): position-key snippet versioning — [arXiv](https://arxiv.org/pdf/2607.26307)
- YC: no YC company dedicated to code decision provenance was found. Adjacent: Memory Store ("Company Brain"; decisions lost across Slack, Granola, Claude chats, and Codex sessions), Mem0 (general agent memory, $24M), and a "Company Brain" category in YC's Summer 2026 RFS — [YC Memory Store](https://www.ycombinator.com/companies/memory-store); [TechCrunch Mem0](https://techcrunch.com/2025/10/28/mem0-raises-24m-from-yc-peak-xv-and-basis-set-to-build-the-memory-layer-for-ai-apps/); [The VC Corner on YC S26 RFS](https://www.thevccorner.com/p/yc-summer-2026-requests-for-startups-ideas)

### Inferences
- The concept is "in the water". Independent convergence (five "Lore"s, plus agent-decisions, CommitLore, Nauro, Decision Guardian, and Adrift) means a bare "decision log for agents" will be read as undifferentiated. Most of these projects have tens of stars, so no OSS standard has won yet.
- Rejected alternatives as a first-class field is now standard in the long tail (agent-decisions, Nauro, the Lore protocol, mcp-server-decisions, lema-mcp). That part of the idea is NOT novel.

## Q4. Overall novelty verdict and precise unclaimed white space

### Takeaway
**Verdict: PARTIALLY EXISTS (trending toward substantially exists).** Each of the five parts exists somewhere, and three tools (Entire, Decispher, agent-decisions) each cover roughly 3 of the 5. No one ships the full loop. Specifically, nobody combines: distilled decision records with first-class rejected alternatives, from multiple agent vendors plus PR/chat; refactor-proof SEMANTIC anchoring of those records to code regions; a pre-merge check that recognizes a semantically re-introduced rejected alternative and cites the dated original reason; all in an open, git-native spec.

### Cited Findings
- No semantic, refactor-proof anchoring of decisions exists in any tool examined. agent-decisions: path anchors that silently disconnect on rename — [agent-decisions](https://github.com/m-zagorski/agent-decisions). Decision Guardian: globs, regex, and line ranges — [decision-guardian](https://github.com/DecispherHQ/decision-guardian). Entire Brain: source anchors whose `verify` "checks source references, not whether a conclusion is correct" — [entire-brain](https://github.com/entireio/entire-brain). Copilot Memory: citations re-validated by the agent, expiring after 28 days — [GitHub blog](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/). Git AI survives rebase and squash, but only for attribution — [Git AI 1.0](https://usegitai.com/blog/introducing-git-ai)
- Pre-merge, semantic, rejected-alternative-reintroduction detection: the nearest are Adrift (design-intent regressions vs ADRs/PR descriptions) — [PyPI adrift-pr](https://pypi.org/project/adrift-pr/); gh-aw (conformance to ONE linked ADR) — [gh-aw](https://github.com/github/gh-aw/pull/33836/files); lema-mcp (plan-time `ruled_out` over RFCs) — [pkgstats](https://www.pkgstats.com/pkg:lema-mcp); Decispher (claimed, method undocumented) — [decispher.com](https://decispher.com/)
- No open standard for decision or rationale records linked to code ranges: Agent Trace is attribution-only — [Thoughtworks Radar](https://www.thoughtworks.com/en-us/radar/platforms/agent-trace). The Lore protocol is per-commit trailers, not per-region — [arXiv 2603.15566](https://arxiv.org/abs/2603.15566)

### Inferences
- **Unclaimed white space (precise):**
  1. **Decision-to-code semantic anchoring as a primitive.** Anchors keyed to AST or symbol fingerprints plus content hashes, re-resolved through rename, move, extract-function, rebase, and squash (including web-UI squash, which breaks git-ai attribution). An anchor-health signal says "decision still governs code / code moved / code deleted / decision orphaned". Nobody does this for decisions.
  2. **Rejected-alternative regression detection at PR time.** A semantic diff classifier that recognizes "this re-adds the pattern rejected on DATE because REASON" (for example, a re-added retry loop). It cites the original session, PR, or chat evidence and the approver. Existing tools check conformance to an ADR, or keyword-match prior decisions, or path-match. None index the REJECTED side as negative patterns tied to code regions.
  3. **An open "decision trace" spec layered on Agent Trace.** Agent Trace answers who, which model, and which conversation per range. Nobody has specified the "why" record (decision, constraints, rejected alternatives, assumptions, approver, supersedes, evidence links) as a portable git-native format that Entire, Cursor, Copilot, Claude Code, and others could all emit and consume. The Lore protocol and CommitLore are commit-level and single-project conventions with low adoption.
  4. **Cross-vendor, multi-source distillation into git (not SaaS).** Decispher does multi-source but is proprietary SaaS with "pointers to files". Entire Brain is open (MIT) but ecosystem-bound and session/doc/git-centric. A neutral distiller that ingests Claude Code, Codex, Cursor, Copilot, and Devin transcripts plus PR threads, issues, and Slack, and writes reviewed records into the repo, is not clearly owned.
- **Risks to the white space:** (a) Entire could close items 2 and 4 within its own platform quickly. (b) GitHub's gh-aw already shows PR-time decision conformance; Copilot Memory plus code review could add durable decision memories. (c) The OSS crowd (five "Lore"s, agent-decisions, CommitLore, Nauro) lowers the barrier. Defensibility would rest on anchoring quality, drift-detection precision (false-positive control, as Adrift emphasizes), and winning the spec, not on the concept.

### Gaps
- No precision or recall data exists for any drift or contradiction tool beyond small self-reported samples (arXiv 2607.29516: 118 samples; IntentDiff: 3/3), so feasibility of low-false-positive semantic drift detection is unproven.
- Did not verify whether any vendor (Sourcegraph, Swimm, Augment, Devin) ships symbol-level anchoring for knowledge records (Swimm historically auto-synced doc-to-code snippets; not checked for 2026 decision features).
